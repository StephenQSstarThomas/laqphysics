# 本轮调试记录与交接边界

## 已定位并处理的问题

| 问题 | 处理 | 核验 |
|---|---|---|
| 旧制备方案的 0.3 峰很低 | 核对旧输入：第一束 F=0.02、12 周期，第二束 F=0.0534、76 周期；筛选更强、更长的第一束和满足 π 面积的较弱第二束 | 保留原绝对谱；新方案附第一束/第二束单独运行的控制组，明确两能区来源 |
| 原始边界历史随时间、内电子网格和角基一起增长 | 末态离子反传，仅保存间隔端点；正向传播时立即收缩当前边界源、累计 complex128 振幅 | 独立旧全历史积分、两种规范、两类角表示和实际 CUDA 圆偏振算例对照 |
| 串行离子回放与 CPU 谱积分耗时明显 | CPU 工作进程回放独立时间块，GPU 累计谱；主进程与工作进程共用分配的 CPU 预算 | CPU 并行/串行和 CPU/GPU 逐复振幅比较；不以最终图相似代替数值对照 |
| 中断可能发生在离子准备期间、或谱检查点刚写好时 | 离子端点准备记录可恢复；两个谱检查点槽与波函数检查点原子配对 | 准备中断、分块恢复、未提交槽故意损坏等测试 |
| 完成传播后报告阶段报 JSON 序列化错误 | NumPy 的整数标签显式转为 Python int | 新增全能区报告测试；实际失败日志与仅重做报告后的成功日志一起保存，传播没有重跑 |
| 旧日志只记录最后一次续跑的求解残差/迭代次数 | 新检查点累计所有传播段的最大真实残差与总迭代次数 | 恢复测试；早期冻结版本的长算例按各段元数据分别保留 |
| Slurm 原脚本的配额与超算配置不一致、logs 创建过晚 | GPU 一卡/16 核，CPU 64 核；提交前创建 logs；拒绝多 MPI rank 重复推进同一算例 | shell 语法与模拟 srun/sbatch 参数核对；本服务器无实际 Slurm 提交记录 |
| 结果分散、图名难辨识、主图可能被归一化误导 | 每次完整任务强制发布含脉冲参数的 SI NPZ/CSV/PNG/PDF；另列条件归一谱 | 输入签名校验、目录 INDEX、实际文件尺寸清单；主图统一绝对概率密度 |

## 怎样判断已完成

只认 `STATUS.json` 的 `state=complete` 且 `complete_spectrum=true`。退出 95 表示有效检查点，尚无完整最终谱。软件通过测试、制备目标通过、生产收敛通过是三件分别报告的事。

当前测试证据在 [validation](../../results/preparation_20260921/validation)，物理结果在 [结果索引](../../results/preparation_20260921/INDEX.md)。前轮线偏振最小交接证据仍在原文档中；本轮没有用新的两脉冲调参结果替代其验收标准。

## 合作者继续完成什么

1. 先用本轮选定脉冲运行 `production/reference`，确认自动产出总谱、2p+1 符合谱及绝对转移率。
2. 完成生产计划中逐个改变的 l、L、径向、dt、表面、截断、吸收层、规范、传播尾时长和最终离子通道检查，以及两个单脉冲控制。
3. 用保留的 projected 历史细化能量、角度和时间求积，再运行审计程序。它同时检查总谱和指定符合谱；新增离子通道会计入总量。
4. 单轴检查通过后，以合并后的参数再确认一次。失败项继续加密，不允许平移能轴“对峰”或单独归一峰高来通过验收。
5. 两脉冲制备确认后，单独设计长探测配置。总谱与符合谱同时分析；需明确源的时间重叠、离子后选择和进一步电离，而不能假定已经离开的旧电子必然出现远程劈裂。

具体命令、参数表和存储说明见 [使用说明](使用说明.md)。完整生产计划仍待超算执行，不能把配置齐备写成已完成全部收敛。

## 复现与数据范围

Git 内交付轻量主谱、图、完整输入、原始运行元数据和冻结数值源码压缩包。全角复振幅、双电子检查点、离子端点与可选投影历史留在持久计算盘，路径和清单见每项 `export.json`。解开 `numerical_snapshots/*.tar.gz` 后，在其目录执行 `make all` 可用目标机编译器重建动态库；原二进制摘要留在快照清单中，不要求跨机器二进制完全相同。

本轮原始 Markdown、参考 PDF 与用户上传 Slurm ZIP 的 SHA-256 均核对未变。没有批量删除旧计算历史。
