# 单电离谱：输入、运行、图和存储

这轮围绕两个目标：让两脉冲制备后的 **0.3 能区成为主信号**，以及让每次完整任务自动交付可直接阅读的单电离谱。当前程序同时输出总谱、指定离子终态的绝对符合谱和单独标注的归一化条件谱。

## 1. 从哪里开始

- 本轮实际结果：[结果索引](../../results/preparation_20260921/INDEX.md)与[结论及剩余工作](../../results/preparation_20260921/SUMMARY.md)。每行直接链接输入、说明和主图。
- 已完成的细化模型输入：[selected_F008_N48_pi201_refined_n3_accelerated.json](../../configs/preparation_20260921/selected_F008_N48_pi201_refined_n3_accelerated.json)。同物理参数的串行前缀另留作数值对照，不计为完成的模拟。
- 超算生产参考输入：[production/reference.json](../../configs/preparation_20260921/production/reference.json)。它比本地调参模型更大，仍需按生产计划收敛，不能把配置文件当成已完成结果。
- 参数设计和物理限制：[算法与物理说明](算法与物理.md)。
- 实际修复、验证证据与合作者待办：[调试与交接](调试与交接.md)。

**一次任务只对应一个输入 JSON。** 原模板复制到 `input_template.json`，实际生效参数写入 `input.json`。输出目录名称含输入文件名、可选标签和参数摘要；图和主谱文件名还包含各束光的 ω、F、周期数、偏振、非零起点。`sp/sm` 分别表示 σ+/σ−，小数点在文件名中写成 `p`。

## 2. 按你的超算配置提交

采用你提供的 ZIP 中已运行的脚本约定：GPU 分区 `GPU40G`、日志放 `logs/`、`HELIUM_PYTHON` 指定解释器。原脚本原样留在 [user_slurm_20260921](../cluster/user_slurm_20260921)。

| 入口 | 节点 | 进程 | CPU 配额 | GPU |
|---|---:|---:|---:|---:|
| scripts/spectra_gpu.slurm | 1 | 1 | 16 核 | 1 张 |
| scripts/spectra_cpu.slurm | 1 | 1 | 64 核 | 0 |

一个进程推进一份双电子波函数。GPU 版使用 GPU 张量运算；CPU 版使用 Torch/Fortran 的线程并行。生产配置另用 4 个单核 CPU 进程提前回放独立离子时间块，主进程线程预算相应扣减。它们不是 MPI 计算副本。4 张卡的节点可以同时放 4 个独立参数任务，每个任务占 1 卡、16 核。

```bash
cd /path/to/laqphysics
export HELIUM_REPO="$PWD"
export HELIUM_PYTHON=/path/to/python
export HELIUM_OUTPUT_ROOT=/persistent/scratch/laqphysics-preparation

# 默认只运行生产计划中的 reference，一卡、16 核。
scripts/submit_spectra.sh gpu

# 或指定一个输入；数组保持单项。
export HELIUM_CONFIG=configs/preparation_20260921/production/reference.json
scripts/submit_spectra.sh gpu --array=0

# 纯 CPU 节点，同一个输入、一个进程、64 核配额。
scripts/submit_spectra.sh cpu --array=0
```

`submit_spectra.sh` 会在提交前创建 logs；Slurm 打开输出日志时，作业内的 mkdir 已经太晚。CPU 分区/account 按你方要求通过 sbatch 参数补充，没有猜测未知分区。这里完成了脚本语法和本机数值路径测试，没有宣称已经在你方 Slurm 控制器上提交。

完整生产与控制输入共有 16 项：

```bash
unset HELIUM_CONFIG
export HELIUM_PLAN=configs/preparation_20260921/production/plan.json
scripts/submit_spectra.sh gpu --array=0-15%4
python scripts/audit_spectra_campaign.py --plan "$HELIUM_PLAN" \
  --out-root "$HELIUM_OUTPUT_ROOT" --tag production
```

上述数组还包含离子通道 n≤3→4 和脉冲后传播 120→240 a.u.。传播完成后，对 `reference` 保留的投影历史再做三项独立求积核验：

```bash
# CASE_DIR 是 reference 的实际输出目录；SNAPSHOT 是其日志打印的代码快照。
# 在已分配 GPU 的作业内可设 HELIUM_DEVICE=cuda:0；默认 CPU 也能执行。
scripts/refine_preparation_spectra.sh "$CASE_DIR" "$SNAPSHOT"
python scripts/audit_spectra_campaign.py --plan "$HELIUM_PLAN" \
  --out-root "$HELIUM_OUTPUT_ROOT" --tag production
```

核验同时约束总谱和 1s、2p+1 符合谱：两能区峰位差 ≤0.001 a.u.、归一形状 L1 差 ≤2%、产额变化 ≤2%。离子扩展核验会把新增通道计入总谱，不会只比较旧通道后误报通过。缺少任一传播或求积结果时，审计保持 pending。各单轴核验通过后，仍应以共同通过的组合参数再确认一遍；若失败，沿相应方向继续加密。

资源估算可在提交前独立运行，不会占用 GPU：

```bash
python scripts/simulate_spectrum.py \
  --config configs/preparation_20260921/production/reference.json \
  --out-root "$HELIUM_OUTPUT_ROOT" --tag production --estimate-only
```

## 3. 输入参数是什么意思

| 参数 | 含义 |
|---|---|
| pulses[].pulse.omega | 载频，原子单位；光子能量为 ω Hartree |
| field | 线偏振峰值电场 F，原子单位；σ± 两分量各为 F/√2，与线偏振具有相同周期平均强度 |
| cycles | sin² 场包络的完整支撑周期数，不是强度 FWHM 周期数 |
| start | 起始时刻，原子单位；1 a.u. 时间约 0.02419 fs |
| polarization | z、sigma+、sigma-；σ+ 吸收的 Δm=+1 |
| dt / post_time / end_time | 最大时间步 / 最后一束光后的传播时间 / 显式结束时刻；有 end_time 时它优先；实际 dt 在 run.json 中，使结束时刻落在整步上 |
| surface_stride | 每隔多少个主时间步采样表面源；本轮为 1。改变它会改变数值求积精度 |
| checkpoint_every | 每隔多少个主时间步保存检查点；需与表面采样对齐 |
| time_integrator / ionic_propagator | 双电子 CF4–Padé / 离子 CF4 四阶传播方案 |
| linear_tolerance / ground_tolerance | 主传播线性方程的真实相对残差容限 / 基态求解残差容限；在线离子求解容限另固定为 1e−12 |
| krylov_dimension / krylov_tolerance | 保留给旧 Arnoldi 传播器；本轮 CF4–Padé 不使用它们，实际 FGMRES 设置记录在 run.json |
| radial.edges / order | 实径向有限元边界（Bohr）/ 每个区间的多项式阶数 |
| tail / ecs_angle / alpha | 无限元阶数、复缩放角和 Laguerre 尺度 |
| lmax / total_Lmax | 单电子角动量上限 / 两电子总角动量上限，需要分别收敛 |
| angular_representation / coulomb_contraction | bipolar 为耦合球谐表示；blocks 按旋转对称性复用库仑矩阵块，不删去电子间相互作用 |
| M=null / natural_parity=false | 圆偏振及不同偏振组合保留所需全部 M 和两类宇称 |
| cutoff_radii / surface | 势的平滑截断区间 / tSURFF 表面，表面模板须在势外和 ECS 桥接点内侧 |
| ionic_channels | 最终离子的 (n,l,m) 列表；“总 SI”仅对这些束缚通道求和 |
| spectrum.energy_segments / spectrum_energy | 优先使用分段网格，每段 [起始能量, 结束能量, 点数]；没有分段设置时才使用旧的统一 spectrum_energy 网格 |
| theta_points / phi_points | 角积分点数；plot_channels 选择主图中显示的离子符合通道 |
| storage.mode | spectrum：仅在线累计谱；projected：另保存小型投影历史，供能量/角度/尾时间重积分 |
| ionic_block_frames | 离子反向传播的存储间隔，默认 128；不是主 TDSE 的时间步或降采样 |
| ionic_device | cpu 为单电子迭代求解；lu 为稀疏直接求解。cuda:0 也是可选路径，但不能同时开启 CPU 回放进程 |
| replay_workers | CPU 离子块回放工作进程数；4 个各用一核，余下预算留主进程 |
| accumulator_device | auto：GPU 任务在 GPU 上累计 complex128 谱振幅，CPU 任务在 CPU 上累计 |
| max_file_bytes | 单文件上限，默认 4,000,000,000 字节；硬上限 5,000,000,000 字节 |
| max_surface_gib | 旧原始通量模式的总历史预算；在线 spectrum/projected 模式不据此分配原始通量 |
| ionic_transfer_times | 在所列时刻假设准备好纯离子 1s，再计算到最终离子通道的转移概率；与双电子实际条件份额分别报告 |
| design | 脉冲设计依据和目标能窗的说明；本轮验收阈值在 observables.json 中明确列出 |

场包络的 π 面积由 D∫F(t)dt=π 设计；实际转移率由含连续态的离子演化核验。不要把 `cycles` 当成拉比周期数。

## 4. 输出在哪里、先看什么

输出根目录有 **INDEX.md / catalog.json**。每个运行目录包含：

| 文件 | 用途 |
|---|---|
| input.json、RUN.md | 完整生效参数及逐束脉冲说明 |
| STATUS.json | running / checkpointed / failed / complete；只有 complete 才有最终谱和图 |
| 含参数标签的 `__SI.png`、PDF | 核心主图：绝对总 SI 谱与绝对离子符合谱，同一刻度 |
| `__SI__conditional.png` | 条件谱，在所计算能窗内各自积分归一；仅用于比较形状 |
| `__SI.npz`、CSV | 小型主数据：energy、angle_integrated、total_density、labels，以及明确标注的条件谱 |
| spectrum.npz | 完整角分辨复振幅和密度，供进一步研究；无需它也能用主数据重画能谱 |
| observables.json | 两能区峰高和产额、2p+1 条件份额、从纯 1s 的绝对离子转移率 |
| resource_estimate.json / output_manifest.json | 提交前估算 / 实际单文件大小清单 |
| checkpoint.npz、surface_online/ | 可恢复波函数、谱积分状态、小型离子端点及可选投影历史 |

主图不把各曲线按自己的峰值归一化。条件图单独标明归一化范围，不能拿其峰高判断 0.3/0.6 的实际信号强弱。完整 SI 还需要离子通道截断、空间、时间和边界收敛；当前写明是求和至哪些 n。

作业达到时限时会留下有效检查点，退出码 95 表示尚无完整最终谱。保持输入、输出根目录和 tag 不变重提即可继续。输出日志会打印代码快照路径；跨代码更新续跑时设置 `HELIUM_SNAPSHOT` 为原快照，避免混用数值版本。数值内核版本不一致时，入口会拒绝复用旧结果；只重画图用 `scripts/render_spectra.py`，用新代码重算则换一个 tag 或输出根目录。一次完成任务必经“传播→谱→命名 PNG/PDF/CSV→complete”，不会只输出波函数就宣布结束。

## 5. flux.npy 能不能删

它是 `[H,Θ]Ψ(t)` 的**复数边界源项历史**，含离子坐标和角通道，不是已经投影好的概率流。完成的主谱 NPZ/CSV/图片不依赖它。删除后无法用它重新选择离子末态、重新投影；旧传播恢复程序也需要原通量前缀。

- 已有有效投影缓存时，改能量/角度求积可以只用该缓存。
- 只保留最终谱时，仍能重画图和统计现有网格；新的网格或离子投影需要重新计算。
- 新任务默认不生成它。projected 模式保存的是小得多的离子收缩结果，不是原始两电子通量。

旧数据先审核，程序会拒绝清理未完成或正在写入的算例：

```bash
python scripts/clean_surface_history.py --out /path/to/completed/case
# 看清清单后执行；无投影缓存且只需最终谱时，明确加 --final-spectrum-only。
python scripts/clean_surface_history.py --out /path/to/completed/case --apply
```

本轮没有批量清除旧研究数据。新任务采用“不写原始通量”的方案，实际文件大小另有清单。分片只是超过单文件上限时的兜底；主要节省来自在线离子收缩和复振幅累计。

### 生产批次的容量预算

当前 16 个生产/控制输入的持久数组估算合计约 **51.77 GB**，最大的单文件估算 **1.851 GB**。其中 reference 约 2.90 GB，ionic_n4 约 5.58 GB 分散在多个文件；这是目录总量，不是一个文件。若保留原始双电子边界历史，相同批次仅这一项就约 3.63 TB。

估算不含独立求积结果、基态缓存、代码快照及日志，也需给原子替换检查点留临时空间；整批建议预留约 **100 GB** 持久 scratch。逐项尺寸和估算范围见 [resource_estimates.json](../../configs/preparation_20260921/production/resource_estimates.json)。这不是 GPU 峰值显存或运行时间保证；每项仍会在启动和最终交付时检查容量。

## 6. 后续长探测

**已加入（2026-09-24）：** 第三束输入、设计依据、快速因子化路径与验证见 [第三束探测](../probe20260924/第三束探测.md)。

当前输入是两脉冲制备。后续探测应另立配置，并同时保留总 SI 和指定离子终态的符合谱。

如果 0.3 电子已经离开相互作用区，仅对离子做局域保迹演化不能自动分裂该电子的无条件能谱。对于近乎单一 1s 离子通道产生的旧电子，后续 π 转移也不能凭空制造能量纠缠。符合后选择、进一步电离造成的 SI 筛选，以及仍有新电子产生的重叠探测，需要分别分析。要让拉比动力学在电子能谱中形成结构，通常需要在电子产生期间驱动离子或另有实际改变电子动量的机制；不能把后续看到的所有新峰都归给“旧 0.3 电子被远程劈裂”。
